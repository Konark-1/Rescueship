# Low-Maintenance Design — Systems That Maintain Themselves

Core thesis (**AD-057**): *if a workflow needs manual bookkeeping, that workflow is a defect to automate, not a procedure to document.* This leaf turns that principle into concrete design moves for any system pool — new or inherited.

## When to Use This Leaf

Descend from `architecture-discipline` when:

- Designing a **new** system and choosing what gets hand-authored vs generated
- A system shows **drift symptoms**: stale indexes, duplicated inventories, docs disagreeing with runtime, the same staleness fixed repeatedly by humans or agents
- Adding a component (CLI, cron job, sub-system) and deciding **where its registration lives**
- Asked to reduce an existing pool's maintenance burden

Do **not** use for:
- Point-in-time deep audits → `system-audit`
- Running post-CRUD linting → `integrity-validation`
- Scaffolding a new pool's directory tree → `system-design`

## The Six Principles

Every hand-maintained surface is classified against these. Each maps to governing ADs/RGs — cite them in ADs you write.

### P1 — Derived over authored
If a document can be computed from declared state (`_org.yaml`, frontmatter, code), it must be generated, never written. Indexes, registries, and AGENTS.md auto-zones are build artifacts.
- Mechanism: `arch emit --all` / `arch emit --agents <pool>` / `arch emit --registry` (AD-061, AD-050)
- Test: *delete the doc — can it be regenerated byte-equivalent?* If no information is lost, it was never a source.

### P2 — Auto-discovery over registration
Filesystem reality is scanned; unregistered components surface as validation failures, not silence. Registration data (description, smoke command) may be authored once — but *existence* must never depend on someone remembering to register.
- Mechanism: `arch cli sync/check` sweeps `systems/*/bin/` for undeclared CLIs — check flags, sync auto-registers with derived metadata (RG-045)
- Test: *create a component and run validate without registering it.* If validate stays green, coverage is incomplete.

### P3 — Validation as compilation
`arch validate` is the make step: it should not only lint structure but compile/link/verify infrastructure dependencies (CLI links, exec bits, gitignore anchoring). `arch validate --fix` promotes checks to repairs.
- Mechanism: CLI-registry tier inside validate (AD-056); structural tiers via system-integrity engine (AD-059)
- Test: *fresh clone + `arch validate --fix`* → full working surface with zero manual steps.

### P4 — Fail-loud gates at every depth
Every node with an operational surface declares its baseline (`smoke.yaml`) and every validator mirrors runtime resolution exactly (RG-019). Depth matters: sub-systems need their own gates, not just pools (AXE-AD-010).
- Mechanism: pool + sub-system smoke.yaml checks in validate; axe pre-tick gate blocks execution on critical failure
- Test: *break a command the gate claims to verify* → gate must go red before any consumer notices.

### P5 — Single-writer stores, fan-out consumers
One CLI owns a store's writes; consumers read canonical state through declared interfaces or adapters — never copies (LB-AD-002 pattern; RG-028 non-duplication). Two writers on one store guarantees drift.
- Mechanism: `services_offered` / `services_consumed` in `_org.yaml`; pooled-symlink OR service call, never both (AD-060 P3)
- Test: *grep for second write paths* (INSERT/UPDATE/write_text against another pool's store).

### P6 — Lossless mutation paths
Automation that touches uncommitted work must preserve it under every failure mode: snapshots before merge/pop, backups before conflict resolution, stash refs never dropped. Destructive shortcuts (`checkout -- .`, `stash drop`, `reset --hard`) are defects even on "shouldn't happen" paths — they happen exactly when parallel agents collide (HI-RG-029).
- Test: *for each destructive command in automation code, name where the overwritten state survives.* No answer = defect.

### P7 — Bootstrap over setup (self-healing from scratch)
A CLI that owns a background process MUST provision its own runtime: systemd user units generated in code (`core/service.py`), content-hash idempotent install, a silent `ensure()` self-heal hook on **every** CLI invocation (missing units installed, inactive/failed timers revived), immediate first-run execution so the very first invocation produces fresh data, flock serialization against interactive syncs, and graceful degradation (`HERMES_NO_SYSTEMD=1` or no user session) that never breaks the foreground verb. A README setup section for services is a design smell — deployment is "install CLIs, run once" (**AD-069**, **HI-AD-071**).
- Mechanism: `core/service.py` per pool with `{install,uninstall,status,ensure}`; `<cli> service status` for inspection; ensure() wrapped in try/except at main() start
- Test: *delete the timer units + stop the timers → run any CLI verb → units re-provisioned and timer active without human action.* Also verified: kill-and-revive on live system (2026-08-23).

## Maintenance Audit Checklist

Run this over an existing pool (this is the audit that produced this leaf):

1. **Inventory every maintained surface**: docs, indexes, registries, manifests, config tables.
2. **Classify each**: AUTHORED (hand-written, has no generator) / DERIVED (generated — verify generator exists and is wired into `arch emit`) / AUTO-DISCOVERED (validator finds absence).
3. **Find redundancy**: an AUTHORED doc whose content overlaps a DERIVED one is RG-010 drift — delete the authored copy, extend the generator instead.
4. **Find silent-failure paths**: surfaces whose absence produces no validation finding (the smoke-at-sub-system-depth gap; undeclared CLIs before auto-discovery).
5. **Find destructive paths** (P6) in any sync/stash/deploy automation in or above the pool.
6. **Find unprovisioned runtimes**: any CLI owning a background process without `core/service.py` bootstrap (P7) is a manual-setup defect.
7. **Fix in order**: silence first (P2/P4), then duplication (P1), writer consolidation (P5), losslessness (P6), bootstrappability (P7).

## Refactor Playbook

| Symptom | Move |
|---|---|
| Hand-written index/table of things derivable from `_org.yaml` | Extend the emitter (`arch emit`), delete the doc (AD-042 precedent) |
| Manual "tools/skills inventory" reference doc | Replace with registry queries (`arch list`, `arch cli check`) — keep only prose knowledge machines can't derive |
| Component exists but unregistered/unlinked | `arch cli sync` auto-registers + links (AD-056) |
| Validator WARN ignored repeatedly | Promote to ERROR if truly invariant, or automate repair behind `--fix`; a warning everyone ignores is worse than silence |
| Two stores holding same domain data | Pick canonical owner (P5), migrate to pointers/fan-out (LB-AD-002 precedent), add LB-RG-003-style sweep guard |
| Same staleness fixed ≥3 times | Stop fixing the instance — automate the class (write the check first, then the fixer) |
| Manual service/cron setup steps in docs; broken timers need human revival | Port to `core/service.py` units-as-code + ensure() hook (AD-069 pattern; logbook/traj reference implementations) |

Org note: low-maintenance design applies to departments too — one capability per department (RG-048 family rule at pool scale); a department nobody staffs is a liability, declare it dormant instead.

## Integration Map — who owns what

| Concern | Command |
|---|---|
| Structural lint + cross-refs + registries freshness | `arch validate` |
| Compile infra deps (links, exec bits, registration) | `arch cli sync` (repair) / `arch cli check` (verify) — also runs inside `validate` |
| Regenerate derived docs/indexes | `arch emit --all` |
| Code-drift + `--reason`/shebang scan | `arch code-scan` |
| Remove superseded docs (SYSTEM.md etc.) | `arch clean superseded` |
| Operational baseline per node | `smoke.yaml` (verified by axe tick gate + validate) |

Write ADs/RGs for decisions taken under this leaf via `decision-logging` / `regression-logging`.
